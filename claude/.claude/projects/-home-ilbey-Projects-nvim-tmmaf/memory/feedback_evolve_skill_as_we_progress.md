When the operator gives a directive or we learn something, **update the `synapse-core-design-system` skill itself** (its `SKILL.md`, sub-skills, `references/*`, and audit scripts) — do not merely save a memory. "Don't just save them as rules. We should update the skills too as we progress." The skill is the durable, executable home for the method; memories are supplementary recall.

**Why:** the skill is the engagement's deliverable + the repeatable tool; a directive that lives only in a memory doesn't reach future skill runs.
**How to apply:** each accepted directive → the matching skill file (e.g. no-hairline → `references/hard-rules.md` + `audit-elevation`; gated stage sequencing + element-targeting granularity → `review/SKILL.md` + parent pipeline; font-loading → `color`/`host` sub-skills referencing `ThemeFontLinks`).
