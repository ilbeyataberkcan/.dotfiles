**KEY ENGINE MECHANICS (learned the hard way):**
- Islands feed the SHARED footer via `flow.setInProgressInput(name,value)` (cve-core `useFlowContext`); footer `FlowSubmitNode` reads `inProgressInput`, gates on `requireFields`, advances (`payloadFromState:true` forwards inProgressInput). `fieldErrors[name]` = inline server errors. NO island-owned advance button (that double-chromes).
- `requireFields` CANNOT gate an array — `fieldSatisfied([])` returns TRUE (any non-null non-string non-bool → true), so an EMPTY multi-select still satisfies the gate. STILL TRUE even after the 10.1.2 array fix below. So array-selection steps MUST write a SCALAR sentinel string ('yes'/'') and gate on THAT (like registration's `documentsComplete`, Belgeler's `filesComplete`). Both the array field AND the sentinel must be declared in `fields[]`.
- `buildStepSubmitSchema` (cve-core transition.js) builds a `.strict()` schema from body-node `name` props + the host-block step's `props.fields`. EVERY forwarded field (incl. the sentinel) MUST be declared in the step's `fields[]` or strict REJECTS the submit (silent re-deliver → "can't advance"). `inProgressInput` is EPHEMERAL per-step (resets on advance) — persisted values live in accumulatedState.
- **MULTI-SELECT ENGINE GAP (FIXED cve-core 10.1.2):** `fieldSchemaFor` had no 'multi-select' case → a multi-select declared in `fields[]` validated as `z.string()`, so an ISLAND writing a string[] was ALWAYS rejected (the array special-case only covered native `flow-multi-select` BODY NODES, not declared fields). This blocked Belgeler (first island-collected array). Fixed: `fieldSchemaFor` returns `z.array(z.string()).optional()` for type 'multi-select' (mirrors the body-node path) — commit cve-core 265416a9, released 10.1.2 (ac476268). tmmaf on ^10.1.2. So S2 islands CAN declare their array via `fields[]` + still need the scalar sentinel for the gate.
- Node-id version is a SINGLE SOURCE: `EVENT_CREATION_VERSION` + `eventCreationNodeId(key)` in fixtures/eventCreationFlow.ts. The injector (get-event-creation-flow.ts `nodeId`) and the injection-seam test derive from it — never hardcode `event-creation/vN/...`. Bump the const + reseed on any tree change.
- Live preview must read a CROSS-STEP accumulator (EventCreationChrome `persisted` seeded from server `initialState`, folded with live `inProgressInput`) — `inProgressInput` is current-step-only.
- Flow versions are immutable+seeded; ANY tree/fields[] change needs a version bump + `bun run seed:event-creation-flow` (now an npm alias). `findDefinitionBySlug` = latest (ORDER BY version DESC). Resume now version-aware (only latest-version drafts) to avoid stale-draft render/advance split.
