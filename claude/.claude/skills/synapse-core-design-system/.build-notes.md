## The confirmed JIT sub-skill load pattern (verified, not assumed)

**Finding.** Claude Code auto-discovery registers only **top-level** `~/.claude/skills/<name>/`
directories as invokable skills. Verified two ways:
- Every `SKILL.md` in the store sits at depth 7 (`~/.claude/skills/<name>/SKILL.md`). No skill nests
  a `SKILL.md` inside a subfolder of another skill — including the `gsd-ns-*` "namespace" skills,
  which are flat **siblings**, not nested children.
- `impeccable` (the canonical multi-stage design skill) keeps ONE `SKILL.md` and pulls deeper docs in
  by explicit instruction — `Consult [typography reference](reference/typography.md)`, `read
  .impeccable.md` — i.e. progressive disclosure via **Read**, not via auto-discovery of nested dirs.

**Consequence for our §10 nested-sub-skill design.** Our nine nested `SKILL.md` files
(`intake/digest/diagnose/color/recompose/review/audit/host/learn`) are **NOT** separately discovered
or invoked by the harness (confirmed: after writing them, only the *parent* appeared in the
available-skills list). So the robust pattern is:

> The parent `SKILL.md` stays lean and **Read-loads** `<subskill>/SKILL.md` just-in-time when that
> stage runs. The nested files are progressive-disclosure modules that happen to be named `SKILL.md`
> (the operator's §10 choice); the parent pulls each in by path, and it in turn pulls its own
> `references/`/`scripts/`/`assets/` one level deeper only if its stage needs them.

This is robust precisely because it depends on **explicit Read**, not on any nested-dir
auto-discovery (which does not happen). The parent body must therefore carry, per stage, a line of the
form: *"Stage N (color) is starting — Read `color/SKILL.md` now and follow it."*

`$SKILL` = `$HOME/.claude/skills/synapse-core-design-system`, set once per run. Visual fidelity
delegates OUT via `Skill → impeccable`; the operator is the final authority (L16).

## One-screen skill-writing checklist (every Draft agent follows this)

From skill-creator's writing guide + §10.3. Hold each SKILL.md to these:

**Progressive disclosure**
- [ ] Each `SKILL.md` < ~500 lines. Push depth into `references/` + `scripts/`, loaded on demand.
- [ ] Parent SKILL.md = mode dispatch + 10-stage spine + Read-load lines + hard rules + contracts.
      No per-stage detail inline — that lives in the sub-skill SKILL.md.
- [ ] Reference files (>300 lines) get a table of contents.

**Voice**
- [ ] Imperative form ("Run the script", "Author the coverage map").
- [ ] **Explain the WHY**, don't pile on ALL-CAPS MUSTs. If you wrote ALWAYS/NEVER in caps, reframe as
      reasoning the model can act on. (The hard rules earn their few imperatives — each cites the gate
      and the lesson behind it.)
- [ ] Pushy triggering description on the parent (all when-to-use lives in `description`): fresh
      realize · drift remediation · "only the colors got themed".

**Determinism (§10.4) — every sub-skill SKILL.md**
- [ ] States its **Deterministic outputs** (always produced for the intent) and its **Nudge-knobs**
      (the bounded recipes/flags/interview answers where creativity enters). No silent variability.

**Scripts, not inline derivation (§6, R3)**
- [ ] Deterministic work ships as a Bun/TS script the skill EXECUTES — never re-derived in prose.
- [ ] The execute-don't-re-derive pattern uses the canonical form, pointing at a real file:
      `bun "$SKILL/scripts/<ns>/<script>.ts" <args>`.
- [ ] Scripts are `#!/usr/bin/env bun`, reuse-first: import package math via the `_vendor` snapshot
      (`sync-vendor` pins `oklch.ts` + `utils.ts`); target inputs (registry, src, theme css) arrive as
      path ARGS at runtime, never hardcoded.

**Honesty / fidelity (L13, L16)**
- [ ] Green tests + a sub-agent "PASS" are necessary-not-sufficient and NEVER the fidelity gate.
- [ ] Fidelity is confirmed by the review surface + `Skill → impeccable` + the operator.

**Validate**
- [ ] Run skill-creator's `quick_validate.py` on each SKILL.md (frontmatter: name + description
      present; body well-formed) before considering a wave done.
